# Safe file operations

1. **Source stories are read-only.** Never edit, move or delete them, and never "enrich" them. `test-design/scripts/safe-file-operations.py` refuses any write outside `<project-root>/test-design/`, which also protects them.
2. **Never write generated artefacts with the Write/Edit tools.** Go through `test-design/scripts/safe-file-operations.py` (temp file, atomic replace, read-back hash check, backup in `test-design/state/backups/`). The only files you create directly are drafts and patches in the session's scratch/temp folder, never inside the project.
3. **Never silently overwrite.** Saving cases is an append (`merge-cases --story-id`) to the story's own file, which leaves existing bytes untouched, so hand edits survive. A `<USER_STORY_ID>-testcase.md` that exists but was never recorded is not appended to without the user's yes (`EXISTS_UNTRACKED`). Replacing an existing case (`replace-case`) or a story's whole file (`regenerate-story-file`: dry run first, then `--yes`, plus `--accept-user-edits` when the file was hand-edited) needs the user's explicit yes first, and a backup is kept.
4. **Track the hash per file.** Record the SHA-256 of each story's file after every save in `workflow.json` (`stories.<id>.testCaseFile.sha256`) and pass it back as `--expect-sha256` on that story's next save. A different hash means the user or a tool edited the file: continue with append-only operations and mention it in the summary.
4a. **One story, one file.** Work on a story touches only `test-design/test-cases/<USER_STORY_ID>-testcase.md`. Do not open, list or hash another story's file while processing a story; the scripts take IDs from `traceability.json` instead. Only the end-of-run and `validate` checks look across files, and they run as scripts.
5. **Corrupt or missing state is not completion.** If `workflow.json`, `traceability.json` or the output file is missing or unparsable, say what is wrong, show the evidence, and ask how to proceed. Never recreate state silently or assume the work was done.
6. **No automatic installation.** If Python 3.9+ is missing, say why it is needed (deterministic validation and safe writes) and ask permission before installing anything. The scripts use only the standard library; never install packages.
7. **Ask before replacing conflicting outputs**: an ID that already exists with different content, a changed source story whose generated cases exist, a `test-design/` folder with a different structure.
8. Never put secrets in any file you write (see `test-data-and-secrets.md`); the scripts refuse content that looks like a secret.
